## 1. Как узнать API личного устройства без подключения

На телефоне открой:

`Настройки -> О телефоне -> Версия Android`

На некоторых оболочках путь называется `Сведения о ПО` или `Информация об
устройстве`.

Соответствие версии Android и API:

| Android | API |
|---|---:|
| 8.0 | 26 |
| 8.1 | 27 |
| 9 | 28 |
| 10 | 29 |
| 11 | 30 |
| 12 | 31 |
| 12L | 32 |
| 13 | 33 |
| 14 | 34 |
| 15 | 35 |
| 16 | 36 |

В Android Studio старые образы обычно ищутся в `Tools -> SDK Manager -> SDK
Platforms`; включи `Show Package Details`. Ничего загружать пока не нужно. Если
API 26-30 всё равно не появятся, следующим отдельным шагом можно проверить
доступные пакеты через `sdkmanager --list` и выбрать совместимый system image.

## 2. Как закрывать API 26-30

Отметь один вариант:

- [x] **AVD API 26 и API 30 (рекомендуется).** Проверяем нижнюю границу `minSdk`
  и верхнюю границу старого opaque fallback; API35 остаётся контрольным.
- [ ] **Один AVD под API моего телефона.** Уже, но быстрее; не доказывает весь
  диапазон API 26-30.
- [ ] **Отложить API 26-30.** Не блокировать разработку, но оставить release
  criterion открытым.
- [ ] Другой вариант:

Разрешаю позже загрузить нужные Android system images: да

## 3. Решение по M4: outcome -> revision

Ни один вариант не будет автоматически менять подтверждённый вывод. Любая
новая формулировка остаётся предложением до явного подтверждения пользователя.

Что должно происходить после добавления результата решения (`outcome`)?

- [x] **Необязательное Review impact (рекомендуется).** Показать локальную
  карточку «Сравнить результат с ожиданием». Пользователь сам открывает её,
  видит outcome, исходное основание и предлагаемый diff, затем подтверждает
  новую revision или отклоняет предложение.
- [ ] **Только сохранить outcome.** Никаких предложений пересмотреть вывод.
- [ ] **Отложить этот срез M4.** Сначала закрыть device/accessibility evidence.
- [ ] Другой вариант:

Нужен ли follow-up/reminder?

- [ ] Нет, только ручное действие.
- [ ] Локальный opt-in reminder, который пользователь назначает сам.
- [x] Одно необязательное предложение срока сразу после выбора.
- [ ] Другой вариант:

Если выбран reminder:

- Предпочтительный срок по умолчанию: 1-3 дня
- Нужны ли системные уведомления или достаточно карточки внутри приложения: пуш уведомления кажется как норм вариант
- Как пользователь должен отменять/переносить follow-up: в пуш пихнуть кнопку для переноса/отмена или заходить в приложение и там переносить
